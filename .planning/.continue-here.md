## Critical Anti-Patterns

| Pattern | Description | Severity | Prevention Mechanism |
|---------|-------------|----------|---------------------|
| Broken similarity ranking formula | SPEC.md's `semantic*0.65 + category*0.15 + location*0.10 + recency*0.10` vs. threshold `0.82` caps any ticket with `location=null, category=OTHER` at a 0.75 ceiling — mathematically unreachable as a duplicate/incident-cluster candidate no matter how semantically identical another ticket is | blocking | Phase 4 must recalibrate the formula/threshold against real seed+evaluation data and include a test proving a `location=null, category=OTHER` ticket can still cross threshold (already captured as REQUIREMENTS.md SIM-03 and a Phase 4 success criterion in ROADMAP.md) |
| Human-only approval gates enforced only by prompt/UI, not data model | `tickets` table (SPEC.md §11.1) lacks `resolved_by_user_id`/`closed_by_user_id` columns, so "only an authorized human closes a ticket" cannot be constrained or audited from the row itself | blocking | Phase 1 must add both columns and enforce transitions via a typed-actor guarded state machine with an exhaustive `(from × to × actor)` matrix test, not prose/UI convention |
| Confidence threshold `<0.70` likely never fires | LLM verbalized confidence is systematically overconfident (research: ~88% stated vs ~79% actual) — the manual-triage safety net FR-004 depends on may be silently disabled | advisory | Phase 3 should add non-confidence manual-triage triggers alongside the raw threshold: `category=OTHER`, `multiple_issues=true`, schema-retry-occurred |

**Do not proceed past Phase 1/Phase 4 planning until the `blocking` rows above are addressed structurally (not just acknowledged).**
